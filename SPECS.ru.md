# Direct Sites — спецификация продукта

Документ описывает версию 0.3.0 и ещё не выпущенный системный режим. Это публичный контракт поведения и ограничений для пользователей и разработчиков.

## Назначение и платформа

Direct Sites — нативная утилита macOS для прямого доступа к выбранным адресам при включённом VPN без изменения системного маршрута по умолчанию. Доменные правила работают через общий HTTP/HTTPS-прокси или отдельную настройку SOCKS5 в браузере; для других приложений предусмотрены IP-маршруты. Это не VPN-клиент и не межсетевой экран.

Сборка предназначена для Apple Silicon и macOS 14+. Проверенная среда — macOS 27 и Swift 6.4. Intel, более ранние macOS, другие VPN-клиенты и восстановление после перезагрузки требуют отдельной проверки. Подпись ad-hoc, нотариализации нет.

## Правила и редактирование

- Принимаются домены, HTTP(S) URL, IPv4 и IPv6. Сохраняется нормализованный хост; путь URL на сопоставление не влияет.
- Отклоняются учётные данные в URL, wildcard, некорректные хосты, неподдерживаемые классы адресов и дубликаты.
- Правило содержит UUID, хост, редактируемое название и необязательный `includeSubdomains`. Не более 200 правил; название — до 120 символов без переносов строк.
- Пустое название заменяется хостом. Фавиконка ищется в HTML главной HTTPS-страницы, затем по HTTPS `/favicon.ico`. При отсутствии изображения используется стандартный значок; заголовок страницы не извлекается.
- Успешные изображения сохраняются в пользовательском кэше и сразу показываются при следующем запуске. Обновление проверяется один раз за запуск. Ошибки повторяются с увеличением задержки, пока открыто окно. Сторонний сервис иконок не используется.
- Для браузерных правил иконки загружаются через локальный SOCKS-прокси. Остальные запросы используют системную сеть. Ошибка прямого подключения не переводит его на VPN.
- Изменения списка действуют после «Применить» и системной авторизации администратора. Закрытие окна с изменениями предлагает отмену или отказ от изменений.
- Очистка всего чернового списка доменов и IP требует подтверждения и включает записи, скрытые поиском, фильтрами или свёрнутыми группами. Отмена сохраняет черновик; «Применить» сохраняет пустой список и удаляет собственные маршруты, сохраняя службы и настройки системного прокси. Кнопка очистки отключена при пустом черновике.
- Сохранённый список и фоновые службы независимы от GUI.

## Доменные правила и прежняя настройка браузеров

Прежний PAC: `http://127.0.0.1:17879/proxy.pac`. Firefox настраивается вручную и должен передавать имена через SOCKS5. Для Chrome сохранено расширение Manifest V3 с разрешением `proxy`, устанавливаемое в каждый нужный профиль. Оно задаёт PAC профиля без изменения системного прокси. Кнопка подготавливает файлы в пользовательском Application Support, копирует путь, показывает его с `~` и открывает менеджер расширений. Приложение не устанавливает расширение скрытно и не редактирует профиль.

PAC направляет нелокальный трафик в службу. `includeSubdomains: true` охватывает основной домен и потомков по границе метки: `example.com` включает `api.example.com`, но не `evil-example.com` или `example.com.other.org`. Точные правила сопоставляют только свой хост. Для IP включение поддоменов недопустимо.

Для совпавших адресов исходящий TCP-сокет привязывается к физическому `en*` через `IP_BOUND_IF` или `IPV6_BOUND_IF`. Доменные правила не создают IP-маршрутов. Остальные адреса используют системную маршрутизацию, включая VPN и существующие host routes. Ошибка прямого соединения не вызывает переход на VPN.

Служба поддерживает HTTP-перенаправление, HTTPS CONNECT и SOCKS5 CONNECT без аутентификации, до 128 одновременных клиентов. UDP, QUIC и SOCKS BIND не поддерживаются. WebSocket использует HTTP Upgrade, WSS — CONNECT. TLS передаётся без изменений. Конфигурация читается для каждого подключения; применение перезапускает прокси и может прервать соединения. Отсутствующая или нечитаемая конфигурация отклоняет запросы.

## IP-маршруты

Root-helper разрешает точные домены через A/AAAA и сверяет host routes каждые 30 секунд через launchd. Ошибка DNS сохраняет кэш. Медленный DNS или системная операция могут увеличить интервал.

Для каждой семьи адресов выбирается первый физический Ethernet/Wi-Fi-шлюз по умолчанию из таблицы маршрутов. VPN-интерфейсы и default routes не изменяются. Исключение охватывает IP целиком для всех приложений, включая другие сайты на том же адресе.

Принадлежность маршрутов сохраняется. Внешние маршруты показываются, но не присваиваются и не удаляются. Удаление правила снимает только принадлежащий службе маршрут с совпадающими текущими адресом, шлюзом и интерфейсом. Общий IP остаётся, пока нужен другому правилу. Ошибка очистки сохраняется для повторной попытки.

## Службы, данные и права

| Объект | Путь или идентификатор |
| --- | --- |
| Приложение | `app.directsites.app` |
| Служба маршрутов и настроек прокси | `app.directsites`, root, launchd RunAtLoad / KeepAlive |
| Служба прокси | `app.directsites.browser`, nobody, launchd RunAtLoad / KeepAlive |
| Helper и конфигурация | `/Library/Application Support/DirectSites/` |
| Правила и маршруты | `rules.json`, `state.json` |
| Системный режим и восстановление | `system-proxy-mode.json`, `system-proxy.plist` |
| Задания launchd | `/Library/LaunchDaemons/` |
| Локальный слушатель | IPv4 loopback `127.0.0.1:17879` |

Установка, изменения и удаление требуют системной авторизации. GUI не получает пароль. Helper валидирует правила, владельца и права системного каталога, сериализует привилегированные операции блокировкой и передаёт аргументы фиксированным системным программам без shell-интерпретации пользовательского ввода.

При обнаружении прежних заданий «Применить» доступно и без изменений правил. Helper проверяет аргументы и идентификаторы прежних служб, останавливает их, запускает новые и удаляет только подтверждённые старые plist. Правила, состояние и маршруты остаются в прежнем системном каталоге. При ошибке запуска предпринимается восстановление прежних служб. Пути не зависят от имени пользователя.

`system-proxy.plist` доступен только root. Признак включённого режима, правила и состояние маршрутов могут читать локальные пользователи; изменяет их администратор. Loopback-прокси не требует аутентификации и доступен другим процессам и пользователям этого Mac. Это не граница изоляции локальных аккаунтов. Loopback, multicast и IPv6 link-local назначения отклоняются, но общей фильтрации частных сетей нет.

`GET /status` содержит счётчики и до 100 совпавших хостов в памяти без URL-путей и учётных данных. Локальные HTTP endpoints требуют точный loopback Host. DNS и иконки небраузерных правил используют системную сеть; отдельной защиты от DNS-утечек нет.

## Удаление и ошибки

Перед остановкой службы отключи системный режим. Удаление восстанавливает принадлежащие приложению системные настройки до остановки служб. Для прежнего режима сначала восстанови настройки Firefox и отключи расширение Chrome. Удаление снимает обе службы, список, helper и принадлежащие маршруты; внешние маршруты сохраняются. Ошибка очистки отображается и допускает повторную попытку. Пустой каталог с lock может остаться.

Статус работающей службы не доказывает доступность сайта. Kill switch, DNS, сторонняя авторизация, IPv6 и разные IP CDN могут мешать. Домены внешней авторизации добавляются отдельно. Для поддоменов браузер должен передавать имя: уже разрешённый IP нельзя надёжно сопоставить исходному домену.

## Навигация по списку (ещё не выпущено)

- Все слова запроса ищутся среди названий, обычного/русского написания доменов, известных IP и замеченных подходящих хостов браузера. Вставленная HTTP(S)-ссылка ищется по домену. Регистр и диакритика не учитываются.
- По умолчанию — сортировка по адресу и группы браузеров/IP-маршрутов. Доступны сортировка по названию/исходному порядку, обратное направление, фильтры всех правил/браузеров/маршрутов/требующих внимания, связанные настроенные домены и список без групп. Родитель берётся из существующих правил без догадок о публичных суффиксах.
- Представление отделено от порядка правил и маршрутизации. Настройки и свёрнутые группы сохраняются для пользователя; запрос — только на текущий сеанс. Поиск временно разворачивает подходящие группы.
- Выбор сохраняется по UUID при обновлениях. Редактирование/удаление находят исходное правило по UUID. Заголовок группы не может стать целью редактирования. Добавление/изменение показывает результат, очищая поиск/фильтр и разворачивая его группу.
- Command-F, Escape, счётчики, пустые результаты, сброс и недоступные действия без выбора. Оба языка интерфейса поддерживаются.
- Контрактные тесты поиска/фильтров/групп/сортировки/сворачивания/идентичности, затем проверка выбора, редактора, обновлений, восстановления настроек и размеров в нативном GUI. Навигационные проверки не должны менять правила и сетевые настройки.

Локально проверено 12 октября 2026: контракты списка, прежние тесты ядра/сокетов и подписанная сборка 6. В установленном GUI с 54 правилами проверены поиск ссылки/названия, пустые результаты/сброс, все варианты группировки, сворачивание/раскрытие при поиске, фильтры, направление сортировки, сохранение выбора, нужный адрес в редакторе с отменой и настройки после перезапуска. Отдельная проверка AppKit проверила компоновку окна при минимальном размере на обоих языках с длинными подробностями. Файл правил побайтово совпадает с исходным, системные HTTP/HTTPS-настройки сохранены.

## Приёмка и проверки

Релиз 0.3.0 повышает версию и номер сборки, включает расширение Chrome в подписанный пакет и публикует arm64 ZIP с SHA-256. Примечания к релизу указывают реально выполненные проверки Chrome и непроверенные ограничения.

- Собрать GUI/helper со Swift 6 и warnings-as-errors.
- Запустить `Source/Tests.swift` без оптимизаций, отключающих assert. Проверяются нормализация, отказы ввода, шлюзы, кэш DNS, общие IP, принадлежность маршрутов, доменные границы, старое декодирование и поиск/повтор иконок.
- Проверить метаданные расширения и копирование в пользовательский Application Support. В тестовом профиле Chrome проверить маршруты совпавшего и обычного домена без изменения системного прокси.
- Проверить обновление прежних идентификаторов, сохранение правил/маршрутов, удаление только подтверждённых заданий и восстановление старых заданий при неудаче.
- Проверить доступность «Применить» для старой установки без изменений правил.
- Проверить Info.plist, глубокую подпись и иконку во всех размерах.
- На тестовом Mac с VPN проверить выбранный домен, поддомен и обычный маршрут для другого сайта.
- Проверить доступность прокси после закрытия GUI и постоянную иконку приложения после выхода.
- Перезагрузку, сон, смену сети, переподключение VPN и удаление проверять отдельно перед заявлением совместимости с другой средой.

Тесты ядра не заменяют привилегированные интеграционные проверки. В релизе перечисляются только выполненные проверки.

## Системный режим (ещё не выпущено)

- Явное включение/отключение HTTP/HTTPS-прокси физических Ethernet/Wi-Fi-служб и основной зарегистрированной службы, включая VPN. Параметры туннеля и default route не изменяются. Состояние включения proxy protocol также сохраняется и восстанавливается.
- Прежний loopback-порт, доменные правила для HTTP и HTTPS CONNECT, сохранение SOCKS5, PAC и status. TLS не расшифровывается.
- Предыдущие управляемые значения сохраняются до записи сетевых настроек. Восстановление при отключении и перед удалением сохраняет посторонние ключи и останавливается при конфликте с активным посторонним прокси. При ошибке данные восстановления сохраняются; повторное включение не заменяет оригинал.
- Выбранный системный режим сохраняется отдельно от данных восстановления. Фоновый launchd-монитор отслеживает изменения сети/прокси через SystemConfiguration и выполняет резервную проверку каждые пять секунд; медленные операции с маршрутами/DNS могут задержать проверку. Очищенные и отключённые настройки восстанавливаются, новые службы сохраняются в резервную копию, активный посторонний прокси вызывает видимый конфликт. Явное отключение сохраняет OFF до возврата настроек, чтобы ошибка возврата не включала режим снова.
- Используются блокировки службы и SystemConfiguration; после commit/apply настройки перечитываются перед успешным завершением.
- Safari, Chrome и Яндекс обычно используют системные настройки; Firefox требует соответствующего выбора. Прежнее расширение Chrome нужно отключить. Скрытого изменения профилей нет.
- IP-маршруты Figma и терминала сохраняются. Программы, игнорирующие системный прокси, и UDP не охватываются этим режимом.
- До реализации добавляются тесты HTTP-адресации и заголовков, forwarding, CONNECT, некорректных запросов, доменных границ, восстановления, повторного включения, внешних изменений и сохранения других параметров.
- Проверяются Swift 6 warnings-as-errors, HTTP/SOCKS и маршруты. Все четыре браузера с VPN, терминал и реальное включение/восстановление проверяются отдельно; недоступные проверки явно отмечаются.

Совместимость HTTP-прокси включает CONNECT HTTP/1.0 без Host и CONNECT с Host без повторного указания порта; явное несовпадение хоста или порта отклоняется.

Локально проверено 6 октября 2026: контрактные тесты и тесты протоколов на сокетах, подписанная сборка arm64, выбранные сайты и обычная HTTPS-страница в Safari, Chrome, Яндексе и Firefox при активном hidemy.name. Адреса исходящих сокетов подтвердили физический интерфейс для выбранного хоста и VPN для обычного. Существующее IP-исключение в терминале подключилось через физический интерфейс, Figma оставалась открытой. Отключение точно восстановило словари прокси всех сетевых служб, включая отключённый протокол прокси VPN; повторное включение прошло успешно. Перезагрузка и переподключение VPN не проверялись.

Локально проверено 12 октября 2026: контрактные тесты политики восстановления, существующие тесты протоколов на сокетах, подписанная сборка arm64, автоматическое восстановление после очистки и отключения HTTP/HTTPS-прокси Ethernet, в том числе при закрытом GUI, и сохранение явного отключения до повторного включения. Beget и обычная HTTPS-страница загрузились во всех четырёх браузерах; Firefox использовал системные настройки. IP-исключения и маршрут VPN по умолчанию сохранились. Восстановление наблюдалось, но максимальная задержка не измерялась; адреса исходящих сокетов, перезагрузка, сон и реальное переподключение VPN в этом прогоне повторно не проверялись.
